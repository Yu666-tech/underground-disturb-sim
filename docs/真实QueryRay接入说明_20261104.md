# 真实 QueryRay 接入说明

日期：2026-11-04。

场景 `coal_face_base` / `0.2.0`，消息协议 `0.1.1`。

## 已实现

新增 ROS 2 包 `coal_scene_query`，读取当前采煤工作面世界的 **collision 碰撞几何**，计算有限线段与箱体、隧道三角网格的相交关系，以及搜索半径内最近表面候选。

使用 `Python/NumPy` 解析 `SDF/DAE`，C++ 编译模块计算线段到三角形的最近距离；不是按基站编号返回预设结果。

当前索引包含 209 个碰撞对象、222116 个三角形。

排除本采煤机 `shearer`，支持当前静态场景；发现其他动态碰撞模型会拒绝启动，不会悄悄漏掉。

文件清单、SHA-256 和能力限制通过 `/platform/v1/query_info` 发布。

场景几何没有改变，因此保留 `scene_version`=0.2.0。

| 入口                      | 用途                                                       |
| ------------------------- | ---------------------------------------------------------- |
| `/scene/query_ray`        | 真实几何服务，类型 `coal_platform_interfaces/srv/QueryRay` |
| `/mock/scene/query_ray`   | 原固定用例模拟服务，保留 MOCK_ONLY 标记                    |
| `/platform/v1/query_info` | String(JSON)，可靠、Transient Local，发布实际来源与哈希    |

## 在当前电脑使用

新启动 `coal-face` 时会随场景自动启动真实查询。

升级前已打开的场景不会自动增加节点：可停止旧场景后重新执行 `coal-face`，也可保留场景，在一个新终端仅启动查询：

```bash
coal_env
ros2 launch coal_platform_bridge real_query.launch.py
```

两种启动方式选一种，避免重复服务。

另开终端运行真实查询示例：

```bash
coal_env
ros2 run coal_platform_bridge query_real_example.py
# 可选择其他当前有效锚点
ros2 run coal_platform_bridge query_real_example.py --ros-args -p anchor_id:=A00
```

示例接收一条有效 UWB raw，复制 `context` 和 `observation_id`，用实际标签/基站坐标查询，输出 `ACTUAL_SCENE_COLLISION_GEOMETRY`、状态、命中 ID、候选数及耗时。

`intersections: 0` 表示该线段未穿过所建模的障碍物，不能为了演示 `NLOS` 人为改成非零。

## B 如何调用

1. 从对应的 `/platform/v1/uwb_ranges_raw` 复制完整 `context`、`observation_id`；每次查询生成新的 `request_id`。

2. `origin_m` 为标签坐标、`target_m` 为基站坐标，均为 `map` 系、单位米。

   当前 `map/world` 完全重合。

3. `reflector_search_radius_m` 范围 0～5 m；设为 0 可跳过候选搜索。

   线段长度大于 1 μm 且不超过 500 m。

4. 等待服务返回，按 `request_id`、`observation_id` 对回原观测。

   仅在 `status`=OK 时使用几何结果。

请求必须属于当前 `experiment/run/robot`，时间戳不能晚于最近已接收真值，也不能落后超过 2 仿真秒。

建议收到 raw 后立即异步查询；启动初期遇到 `TIME_UNAVAILABLE` 可短暂等待真值后重试。

源文件大小/修改时间变化会触发 `VERSION_MISMATCH`，须重建查询节点；几何改动还应按场景版本规范更新版本。

该节点不能检测 Gazebo GUI 中临时插入或移动的静态物体，当前约束为运行中不改动静态场景。

## 返回值怎么理解

- `direct_intersections`：按距起点距离排序，含几何 ID、类型、交点、法向。

  BOX 提供入/出点、法向厚度及实际线段穿过长度；起点位于内部时返回从起点开始的区间。

- MESH：返回真实三角表面交点，但不假设网格封闭。

  `entry/exit` 同为表面点，`thickness_m/path_length_m` 为 NaN，消费端不可把它解释成零厚度。

  法向依网格顶点顺序，未验证朝外。

- `reflector_candidates`：每个碰撞体在搜索半径内的最近表面候选，含最近点、距离和法向；尚未验证镜面反射、可见性或额外路径，不能直接作为真实多径。

- `material`、`reflection_level`：当前缺少传播参数，均明确返回 `UNKNOWN`。

  视觉贴图不等于电磁材料属性。

- BOX 使用闭实体边界，贴面穿行可产生命中并附提示；相邻/重叠箱体可能返回重叠区间，计算总穿透长度前必须合并区间，不能简单相加。

  孤立零长度相切忽略。

- `status`=OK 时 `error_message` 可包含能力提示，例如网格厚度未知；错误状态则不返回部分几何。

  超过 4096 个交点或 256 个候选会返回 `UNSUPPORTED`，可减小搜索半径。

本服务提供场景几何事实，不修改 `truth/raw`，也不输出扰动后 observed；B 负责传播与 UWB 误差模型，C 继续负责激光退化模型。

## 验证结果

| 核查项                                    | 结果                                    |
| ----------------------------------------- | --------------------------------------- |
| 支架实体、间隙、高度、隧道网格、候选表面  | 全部通过                                |
| 支架实体示例                              | 距起点 1.05 m 命中，线段穿过长度 1.20 m |
| 与 Gazebo ODE 自身物理射线核对            | 6 例通过，最大距离差 7.4002×10⁻⁸ m      |
| 场景/版本/坐标/run/半径/协议/NaN 非法请求 | 返回相应拒绝状态，全部通过              |
| 当前实际 9 条基站链路                     | 查询成功，测试时刻均无直接遮挡          |
| 原真值、扫描、RobotState                  | 独立场景联调期间持续接收                |
| 真实/模拟服务并存、真实调用示例           | 通过                                    |

本机独立联调的短线段查询约 2～5 ms；9 条实际链路含 2 m 候选搜索时，端到端耗时约 6～86 ms，P95 约 84 ms。

该结果不是持续 90 次/秒的吞吐量证明；大量候选下应控制查询频率，按需关闭候选搜索，再做 B 的持续负载验收。

原始证据文件：`geometry_tests.json`、`gazebo_native_comparison.json`、`service_acceptance.json`。

公开精简记录见仓库 evidence/。

测试采用独立 ROS Domain 和 Gazebo 端口，未停止原有场景，未修改 `Ubuntu20/ROS1`。

远端源码版本以仓库提交为准。
